## 甲 负责领域 —— Agent 底层设施

### 模块1：短期记忆（Working Memory）

**目标**：对话过长时自动压缩旧消息为摘要，保证 Agent 不丢上下文。

| 子任务 | 说明 |
|---|---|
| Token 估算器 | 基于模型 Tokenizer 估算消息 Token 数 |
| 触发判定 | 超过 context window × 阈值（默认 50%）时触发 |
| LLM 摘要压缩 | 保留 system prompt + 当前轮次 + 近 N 条消息，其余 LLM 压缩为 Memory Summary |
| tool_call 边界保护 | 确保 assistant tool_call 和 tool result 配对不被打断 |
| 降级策略 | LLM 摘要失败 3 次 → fallback 原始文本归档 |

**交付标准**：100 轮对话后 Agent 仍能记住早期关键事实，Token 不超限。

**核心技术**：Token 估算、滑动窗口、LLM 摘要

---

### 模块2：长期记忆（知识图谱）

**目标**：跨会话持久化记忆，下次对话自动检索相关历史。

| 子任务 | 说明 |
|---|---|
| Neo4j 接入 | 图数据库连接管理 + Schema 初始化 |
| MemoryRepository | Episode / Entity / Relationship 的图读写接口 |
| 记忆提取 | 对话结束后 LLM 提取实体和关系（JSON Schema 约束输出） |
| 记忆检索 | query 提取关键词 → 图谱匹配实体 → 返回关联 Episode |
| MemoryContext 注入 | 检索到的记忆注入 Agent 上下文 |

**交付标准**：用户说"上次讨论的 X" → Agent 检索到上次对话中的 X 并延续。

**核心技术**：`Neo4j`、LLM 结构化提取、知识图谱检索

---

### 模块3：Agent 工具集

**目标**：定义统一 Tool 接口，实现 Agent 可用的工具清单。

| 子任务 | 说明 |
|---|---|
| Tool 接口定义 | `Name()` `Description()` `Parameters()` `Execute()` |
| 知识库检索工具 | 将阶段一的检索能力包装为 Tool |
| Web 搜索工具 | 将阶段一的 web_search 包装为 Tool |
| 数据计算工具 | 生成 Python 代码 → 调沙箱执行 → 返回结果 |
| 最终答案工具 | FinalAnswer，Agent 输出最终回复的出口 |
| MCP 工具加载 | 从外部 MCP Server 动态发现并注册工具 |
| 参数校验 | JSON Schema 校验 + Go 类型自动转换 |

**交付标准**：至少 4 个工具可被 Agent 调用，Tool 接口清晰。

**核心技术**：Function Calling、JSON Schema、MCP Client

---

### 模块4：Python 沙箱

**目标**：为数据计算工具提供隔离的 Python 代码执行环境。

| 子任务 | 说明 |
|---|---|
| 进程管理 | 启动 Python 子进程，stdin/stdout 交互 |
| 安全限制 | 禁止文件写入、网络访问、危险内置函数 |
| 超时控制 | 单次执行超时自动终止 |
| DuckDB 集成 | 沙箱内预装 DuckDB，支持 SQL 分析 |
| 结果序列化 | 执行结果（文本、DataFrame、图表）结构化返回 |

**交付标准**：Agent 说"分析表格季度趋势" → 检索数据 → 沙箱执行 Python → 返回分析结果。

**核心技术**：Python subprocess、DuckDB、沙箱安全策略

## 乙 负责领域 —— Agent 应用编排

### 模块5：Agent 引擎 + Skills

**目标**：实现 ReAct 推理循环，这是阶段二的核心模块。

| 子任务 | 说明 |
|---|---|
| ReAct 循环 | think → act → observe → finalize，最大迭代次数控制 |
| Agent 配置 | max_iterations、temperature、allowed_tools |
| Skills 系统 | 加载 Markdown 技能定义文件，注入 system prompt |
| Agent Session | Agent 模式会话管理，关联 Tool 调用历史 |
| 自定义 Agent | 用户可创建配置自己的 Agent（名称、提示词、模型、工具） |
| eino 框架编排 | 用 eino 的 Chain/Graph 机制编排思考-行动流程 |

**交付标准**：创建 Agent → 配置工具和技能 → 提问 → ReAct 多步推理 → 答案。

**核心技术**：`eino` 框架（Chain/Graph）、ReAct 模式、Function Calling

---

### 模块6：MCP 服务

**目标**：将知识库检索能力暴露为 MCP Server，让外部客户端（Claude Desktop 等）能调用 DocMind。

| 子任务 | 说明 |
|---|---|
| MCP Server 协议 | 支持 stdio 和 SSE 两种传输 |
| 资源暴露 | 将知识库 chunk 检索包装为 MCP Resource |
| 工具暴露 | 将知识库搜索包装为 MCP Tool |
| MCP Client 管理 | Agent 调用外部 MCP 工具的注册与启停 |

**交付标准**：Claude Desktop 通过 MCP 连接 DocMind，搜索知识库并返回结果。

**核心技术**：MCP 协议（stdio / SSE）

---

### 模块7：Wiki 引擎

**目标**：批量 Markdown 文档管理，自动维护 `[[页面名]]` 链接关系。

| 子任务 | 说明 |
|---|---|
| Wiki 页面 CRUD | 创建/编辑/删除，关联到知识库 |
| 批量导入 | 递归导入目录下 .md 文件 |
| 链接识别 | 识别 `[[页面名]]` 格式，建立页面引用图 |
| 链接修复 | 检测失效引用，批量修复或报告 |
| 内容 Lint | 格式校验与自动修正 |

**交付标准**：导入 100 篇 Markdown → 建立页面链接网 → 搜索时关联引用关系。

**核心技术**：Markdown 解析、正则匹配

### 模块8：IM 集成层

**目标**：通过飞书、企微等 IM 工具与知识库对话。

| 子任务 | 说明 |

**核心技术**：Webhook、消息队列、平台 SDK

### 接口契约

甲交付给乙的核心接口（阶段二新增）：

```go
// 甲实现
type Consolidator interface {
    ShouldConsolidate(currentTokens int) bool
    Consolidate(ctx, messages []Message) ([]Message, error)
}
type MemoryService interface {
    AddEpisode(ctx, userID, sessionID string, messages []Message) error
    RetrieveMemory(ctx, userID, query string) (*MemoryContext, error)
}
type Tool interface {
    Name() string; Description() string
    Parameters() map[string]interface{}
    Execute(ctx, args map[string]interface{}) (string, error)
}
type Sandbox interface {
    Execute(ctx, code string) (*SandboxResult, error)
}
```

乙拿到这些接口后组装 Agent 引擎：

```go
// 乙在 Agent 引擎中组装甲的组件
engine := NewAgentEngine(
    chatModel,        // 阶段一的 Chat
    toolRegistry,     // 甲的 Tool 集合
    consolidator,     // 甲的短期记忆
    memoryService,    // 甲的长期记忆
    skills,           // 乙的 Skills 系统
)
```
