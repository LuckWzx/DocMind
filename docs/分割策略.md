# 分割策略

> 本文档描述 DocMind 知识入库链路的文本分块策略，对应实现：
> `internal/service/chunker_service.go`（分块算法）与 `internal/service/knowledge_service.go`（入库调用）。
> 最后更新：2026-08-06（修复 200 块截断、新增受保护内容机制、增强标题检测）。

## 1. 分块在系统中的位置

```
上传文件 → DocReader 解析为 Markdown → 分块 → 保存 chunks → 向量化 → pgvector
                                        ↑
                                    本文档描述
```

- **入库链路**：`knowledge_service.processUploadAsync` → `buildMarkdownChunks` → `splitUnits`（**无数量限制**）
- **预览链路**：`POST /v1/chunker/preview` → `splitPreviewUnits`（**截断前 200 块**，仅用于前端预览展示）
- 分块配置挂在**知识库**上（`KnowledgeBase.ChunkingConfig`），按知识库粒度生效
- 分块是**离线入库阶段**的能力，与在线问答（Agent 编排 / 向量检索 Tool）完全解耦

## 2. 配置项

| 配置项 | 默认值 | 取值范围 | 说明 |
|---|---|---|---|
| `chunk_size` | 512 | 100 ~ 4000 | 目标分块大小（按字符数，rune 计数） |
| `chunk_overlap` | 80 | 0 ~ chunk_size/2 | 相邻分块重叠字符数 |
| `separators` | `["\n\n", "\n", "。", "！", "？", ";", "；", " "]` | — | 分隔符优先级列表，依次尝试 |
| `strategy` | `auto` | `auto` / `heading` / `heuristic` / `legacy` | 切分策略 |
| `enable_parent_child` | false | — | 是否启用父子分块 |
| `parent_chunk_size` | 4096 | 512 ~ 8192 | 父块大小（父块之间无 overlap） |
| `child_chunk_size` | 384 | 64 ~ 2048 | 子块大小 |
| `token_limit` | 0 | — | Token 上限（预留，当前按字符切分） |
| `languages` | [] | — | 语言提示，辅助文档特征分析 |

## 3. 策略分级（auto 自动决策）

`selectChunkingTier` 基于文档特征分析结果（`buildDocProfile`）逐级决策：

```
┌─ 显式指定 strategy？─────────────────┐
│  heading / heuristic / legacy 直接采用  │
└──────────────────────────────────────┘
                     ↓ auto
┌─ 标题信号充足？────────────────────────┐
│  MDHeadingTotal + 中/英/德章节数 ≥ 2     │→ heading
│  或 NumberedSectionCount ≥ 3            │
│  或 (AllCapsShortLineCount ≥ 3          │
│     且 AllCapsShortLineCount >          │
│        RepeatedFooterCount)             │
└──────────────────────────────────────┘
                     ↓ 否
┌─ 结构信号存在？────────────────────────┐
│  BlankParagraphBreaks > 0              │→ heuristic
│  或 NumberedSectionCount > 1           │
│  或 VisualSepCount > 0                 │
└──────────────────────────────────────┘
                     ↓ 否
┌─ legacy：纯长度递归切分 ────────────────┐
```

### 文档特征分析（buildDocProfile）

| 特征 | 说明 |
|---|---|
| `MDHeadingTotal` / `MDHeadingCounts` | Markdown `#` 标题数量与各级分布（`^(#{1,6})\s+`） |
| `ChineseChapterCount` / `EnglishChapterCount` / `GermanChapterCount` | `第X章` / `Chapter N` / `Kapitel N` 章节数 |
| `NumberedSectionCount` | 编号标题数（`1.`、`1.2.3`、`1、`、`1)`） |
| `AllCapsShortLineCount` | ≤40 字符的全大写短行数（英文标题特征） |
| `RepeatedFooterCount` | 重复出现的短行数（页眉页脚特征，用于排除误判） |
| `BlankParagraphBreaks` | 空行段落数（`\n\n` 出现次数） |
| `VisualSepCount` | 视觉分隔线数（`---` / `___` / `===`） |
| `HasTables` / `HasCode` / `CodeRatio` | 表格 / 代码块 / 代码占比 |
| `DetectedLangs` | 检测语言（zh/en/de，叠加 languages 提示） |

## 4. 三种切分策略

### 4.1 heading（标题结构切分）

1. `parseMarkdownSections` 识别标题行：
   - **优先 Markdown `#` 标题**（`^(#{1,6})\s+`，层级 1~6）
   - 无 `#` 标题时回退识别**结构化文本标题**（PDF 等解析结果常见）：
     - 中文章节：`第X章/节/部分/篇`（level 1）
     - 英文/德文：`Chapter N` / `Kapitel N`（level 1）
     - 编号标题：`1.`、`1.2.3` 等，层级由编号深度推导（`1.2.3` → level 3）
     - 全大写短行（≤40 字符），**排除重复行**（页眉页脚每页重复出现，不当标题）
2. 以标题为边界切分章节，维护标题路径栈
3. 每个章节内再按 `splitRecursive` 切分
4. 分块的 `ContextHeader` 为标题路径（如 `2. 方法 / 2.1 数据来源`），写入 chunk 元数据，检索时携带上下文

### 4.2 heuristic（结构感知切分）

按 `\n\n` 切分为段落，再用 `packSegments` 将段落打包为分块：
- 优先保留段落边界
- 段落超限时退化为 `splitRecursive` 递归切分

### 4.3 legacy（长度优先切分）

直接对全文执行 `splitRecursive` 递归切分，适合无标题、无段落结构的连续文本。

## 5. 递归切分算法（splitRecursive）

```
文本 > chunk_size？
  ├─ 否 → 整体作为一个分块
  └─ 是
      ├─ 存在受保护内容？ → 拆为原子段（受保护段保持整体），
      │                    普通段递归切分，packSegments 打包
      ├─ 按分隔符优先级切分（splitKeepingSeparator，保留分隔符）→
      │  packSegments 打包；打包结果 >1 块则返回
      └─ 兜底 splitByRunes 按字符硬切（切分点避开受保护区间）
```

### packSegments（智能打包）

- 尽量将段落/句子拼接进同一分块（以 `\n\n` 连接）
- 超出 `chunk_size` 时提交当前分块，并保留末尾 `chunk_overlap` 字符作为下一块开头（overlap）
- overlap 截断点（`tailRunes`）**避开受保护区间**，前移至区间起点（最多前移 2×overlap）

## 6. 受保护内容机制

分块时以下内容作为**不可切分单元**整体保留，避免路径/引用被拦腰切断：

| 类型 | 模式 | 示例 |
|---|---|---|
| Markdown 图片/链接 | `!?\[[^\]]*\]\([^)]*\)` | `![image_1.png](images/image_1.png)` |
| 代码块 | 成对 ```` ``` ```` | 多行代码整体 |
| 表格 | 表格行（连续行自动合并，行间仅隔换行） | `\| 姓名 \| 年龄 \|` |
| URL | `scheme://...` | `https://example.com/a.pdf` |
| Windows 路径 | `[A-Za-z]:\\...` | `D:\GoLang\DocMind\data\files` |

约束：
- 受保护片段长度 **≥ chunk_size 时允许硬切**（无法整体保留，与 Python 端 splitter 行为一致）
- 重叠区间自动合并（如表格单元格内嵌链接）

## 7. 父子分块（enable_parent_child）

```
全文
 ├─ 父块1（≈parent_chunk_size，无 overlap）
 │    ├─ 子块1.1（≈child_chunk_size，overlap 生效）
 │    ├─ 子块1.2
 │    └─ ...
 ├─ 父块2（≈parent_chunk_size，无 overlap）
 │    └─ ...
 └─ ...
```

- 父块按 `parent_chunk_size` 切分（overlap = 0），子块在父块**内部**按 `child_chunk_size` + `chunk_overlap` 切分
- 子块继承父块的 `ContextHeader`（标题路径）
- 注意：父块边界处的内容在子块层面是硬断开的（子块不跨父块）

## 8. 入库与预览的差异

| 链路 | 函数 | 分块数量 |
|---|---|---|
| 入库（buildMarkdownChunks） | `splitUnits` | **无限制**（修复前误用预览函数，超过 200 块被截断丢失） |
| 预览（/v1/chunker/preview） | `splitPreviewUnits` | 截断前 200 块（仅展示用） |

两链路共用同一算法，预览效果即入库效果。

## 9. 已知取舍与注意事项

- **标题识别偏保守**：全大写短行要求唯一出现（排除页脚）；PDF 若标题非章节/编号/全大写格式，auto 可能回退 heuristic
- **PDF 解析端**（`pkg/docreader/parser/pdf_parser.py`）输出纯文本 Markdown（无 `#` 标题），依赖本策略的结构化标题识别；若需更精确的标题层级，可后续在 Python 端按字体大小输出 `#` 标题
- **分块配置变更不追溯**：修改知识库分块配置后，已入库的知识条目不会自动重新分块，需重新上传
- 字符计数按 rune（中文 1 字符 = 1 rune），`SizeTokensApprox ≈ 字符数/4` 仅为预览估算，非真实 token
