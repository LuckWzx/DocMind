# 知识库问答agent注意事项



这是一个非常好的问题，也是很多人开发 Agent 最容易忽略的地方。

很多人认为**知识库 Agent = RAG + LLM**，实际上真正企业能上线的 Agent，**RAG 只占整个系统的 20% 左右**，另外 80% 都是围绕用户体验、可靠性、可控性、人机交互来做的。

如果你的目标是做一个**企业知识库问答 Agent（适合写进简历）**，我建议从下面几个维度设计。

------

# 一个优秀 Agent 的评价标准

我一般把 Agent 分成 8 个能力。

```
                Agent

      ┌────────────────────┐
      │    用户体验 UX      │
      └────────────────────┘

  理解能力
  检索能力
  推理能力
  工具能力
  记忆能力
  可控能力
  容错能力
  可观测能力
```

企业真正关注的是：

> 不是回答得多聪明，而是是否稳定、可控、用户体验好。

------

# 第一部分：用户交互（最重要）

很多 Demo 没有人机交互。

真正 Agent 第一件事就是：

> 用户体验。

例如：

```
用户：
公司的请假制度是什么？

Agent：
我正在查询公司制度...

（开始检索）

已找到3份制度

正在综合答案...

回答...
```

这种体验就比：

```
......

（等8秒）

回答
```

好很多。

所以需要：

## ① Thinking（思考状态）

例如：

```
🤔 正在思考...

📚 正在查询知识库...

🔍 正在分析文档...

✍️ 正在组织答案...
```

这些其实就是 SSE 一点一点推送。

------

## ② Streaming（流式回复）

不要等模型全部生成完。

应该：

```
你好，根据员工手册...

第一条...

第二条...
```

边生成边输出。

------

## ③ 中断回复（Abort）

这个非常重要。

例如：

```
AI：
第一条......

第二条......

第三......
```

用户突然点：

```
停止回答
```

Agent 应该：

```
取消LLM
取消Retriever
取消Workflow
关闭Tool
```

Go 里面就是：

```
context.Cancel()
```

所有节点都监听 Context。

这也是很多 Agent 框架（包括 Eino 等）都会重点支持的能力。

------

## ④ Retry（重新生成）

回答不好：

```
重新回答
```

不能重新检索整个知识库。

应该：

```
沿用已有检索结果

重新Prompt

重新生成
```

速度快很多。

------

## ⑤ Continue（继续回答）

例如：

```
回答长度限制
```

用户：

```
继续
```

Agent：

```
继续生成剩余内容
```

------

## ⑥ 打字机效果

就是：

```
你
你好
你好，
你好，根据...
```

用户会感觉速度更快。

------

# 第二部分：RAG能力

真正企业知识库，RAG 才是核心。

应该考虑：

```
Query

↓

Query Rewrite

↓

Retriever

↓

Rerank

↓

Prompt

↓

LLM
```

------

## Query Rewrite

例如：

用户：

```
怎么报销？
```

改写：

```
公司的费用报销流程是什么？
```

提高召回率。

------

## Multi Query

例如：

```
公司的福利有哪些？
```

拆成：

```
员工福利

五险一金

节假日福利

补贴
```

然后分别检索。

------

## Hybrid Search

不要只有向量。

最好：

```
BM25

+

Embedding
```

融合。

------

## Rerank

Retriever 找：

```
Top20
```

然后：

```
BGE Reranker

Cohere Rerank

Jina Rerank
```

排序。

最后：

```
Top5
```

给LLM。

------

## 引用来源

回答：

```
根据《员工手册》第12页...
```

而不是：

```
AI觉得...
```

最好：

```
来源：

员工手册.pdf

制度.docx

网址
```

------

# 第三部分：记忆

很多 Demo 没有。

实际上：

```
用户：

刚刚我们说到哪里？
```

Agent：

```
上一轮讨论的是...
```

需要：

## 短期记忆

Session Memory

例如：

```
Redis

Memory

Conversation
```

------

## 长期记忆（可选）

例如：

```
用户喜欢回答简洁

喜欢Markdown

喜欢中文
```

以后自动调整。

知识库 Agent 通常不是必须，但可以作为增强能力。

------

# 第四部分：工具调用（Tool）

即使知识库 Agent，也不应该只能聊天。

例如：

```
查文档

查数据库

查API

查OA

查CRM

查Git

查Jira
```

例如：

```
请帮我查询我的年假余额
```

Agent：

```
Tool：

HR API
```

而不是：

```
知识库没有...
```

------

# 第五部分：可控性（企业非常关注）

例如：

## 敏感词

```
工资

薪资

裁员
```

是否允许回答。

------

## 权限

例如：

普通员工：

```
只能看员工制度
```

HR：

```
还能看薪资制度
```

Retriever 前：

```
Filter

department

role

tenant
```

------

## 幻觉控制

例如：

Retriever 没找到。

不要：

```
AI瞎编。
```

应该：

```
没有找到相关资料。

以下内容可能不是企业官方规定。
```

------

## 置信度

例如：

```
回答可信度：

92%
```

或者：

```
引用文档数量：

3
```

------

# 第六部分：异常处理

企业 Agent 必须考虑：

```
LLM超时

Embedding失败

Milvus异常

Redis异常

Tool失败
```

例如：

```
知识库检索失败

正在降级...
```

改成：

```
直接LLM
```

或者：

```
请稍后重试
```

而不是：

```
500
```

------


# 如果这是一个企业级知识库 Agent，我建议至少实现这些功能

| 模块                             | 是否建议   | 优先级 |
| -------------------------------- | ---------- | ------ |
| SSE 流式输出           | ✅ 必须     | ⭐⭐⭐⭐⭐  |
| 停止回答（Abort）                | ✅ 必须     | ⭐⭐⭐⭐⭐  |
| 多轮对话                         | ✅ 必须     | ⭐⭐⭐⭐⭐  |
| Query Rewrite                    | ✅ 必须     | ⭐⭐⭐⭐   |
| Hybrid Search（BM25+向量）       | ✅ 建议     | ⭐⭐⭐⭐   |
| Rerank                           | ✅ 建议     | ⭐⭐⭐⭐   |
| 文档引用（Source）               | ✅ 必须     | ⭐⭐⭐⭐⭐  |
| 检索无结果降级                   | ✅ 必须     | ⭐⭐⭐⭐⭐  |
| Tool Calling（查 OA/数据库/API） | ✅ 建议     | ⭐⭐⭐⭐   |
| 权限过滤（ACL）                  | ✅ 企业必备 | ⭐⭐⭐⭐⭐  |
| Trace 链路追踪                   | ✅ 建议     | ⭐⭐⭐⭐   |
| Prompt 版本管理                  | ✅ 建议     | ⭐⭐⭐⭐   |
| Token 与耗时统计                 | ✅ 建议     | ⭐⭐⭐⭐   |
| 重试、继续生成                   | ✅ 建议     | ⭐⭐⭐⭐   |

## 如果你打算用 **Go + Eino** 做一个能写进简历、接近企业生产环境的项目，我建议采用下面的架构：

```
前端（Vue / 小程序）
        │
        ▼
WebSocket（支持流式、中断、重试）
        │
        ▼
Agent Controller
        │
        ├── Session Manager（多轮上下文）
        ├── Abort Manager（context.Cancel）
        ├── State Manager（Thinking / Searching / Generating）
        ├── RAG Pipeline
        │     ├── Query Rewrite
        │     ├── Hybrid Retriever（Milvus + BM25）
        │     ├── Reranker
        │     └── Prompt Builder
        ├── Tool Manager（数据库、HTTP API、企业系统）
        └── LLM Adapter（DeepSeek、Qwen、OpenAI 等）
                 │
                 ▼
        Trace / Logging / Metrics
```

这套设计不仅功能完整，而且覆盖了企业级 Agent 的核心能力：**流式交互、可中断、可靠检索、权限控制、可观测性和可扩展架构**。如果这些模块都实现并配有完整文档和演示，它已经不只是一个简单的 RAG Demo，而是一个具备较强工程价值的知识库 Agent 项目。
