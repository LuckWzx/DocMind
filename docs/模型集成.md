# 模型集成层

> 统一封装 AI 模型调用，对上层业务屏蔽不同厂商/部署方式的差异。

---

## 整体架构

```
上层业务（service / agent）
        │
        ▼
┌───────────────────────────────────────┐
│           模型集成层（models/）         │
│                                       │
│  Chat    Embedding   Rerank   VLM  ASR│
│  接口     接口        接口      接口  接口│
│   │        │          │        │     │
│   ▼        ▼          ▼        ▼     ▼
│  ┌──────────────────────────────┐     │
│  │       provider 注册表         │     │
│  │  openai / aliyun / zhipu /  │     │
│  │  deepseek / gemini / ... 22个│     │
│  └──────────────────────────────┘     │
│                                       │
│  装饰器链: LLMDebug → Langfuse       │
└───────────────────────────────────────┘
        │
        ▼
    外部 AI API
```

**五条能力线**，每条都是"接口 → 工厂函数 → 多厂商实现"，通过 `provider` 注册表自动路由。

| 目录 | 核心接口 | 作用 |
|---|---|---|
| `chat/` | `Chat` | 对话/工具调用（最复杂） |
| `embedding/` | `Embedder` | 文本向量化 |
| `rerank/` | `Reranker` | 检索结果重排序 |
| `vlm/` | `VLM` | 图片理解/描述 |
| `asr/` | `ASR` | 语音转文字 |
| `provider/` | `Provider` | 厂商注册表 + 自动检测 |

## 一、Chat 接口（chat/chat.go）

最核心的接口，被 Agent 引擎和会话管道直接调用。

### 接口定义

```go
type Chat interface {
    Chat(ctx, messages []Message, opts *ChatOptions) (*types.ChatResponse, error)
    ChatStream(ctx, messages []Message, opts *ChatOptions) (<-chan types.StreamResponse, error)
    GetModelName() string
    GetModelID() string
}
```

### 核心类型

```go
type ChatOptions struct {
    Temperature      float64     // 温度
    MaxTokens        int         // 最大输出 Token
    Thinking         *bool       // 思考模式（DeepSeek 等）
    Tools            []Tool      // Function Calling 工具定义
    ToolChoice       string      // "auto" / "required" / "none"
    ParallelToolCalls *bool      // 是否允许并行工具调用
}

type Message struct {
    Role         string               // system / user / assistant / tool
    Content      string               // 文本内容
    MultiContent []MessageContentPart // 多模态（文本+图片）
    ToolCallID   string               // tool 角色专用
    ToolCalls    []ToolCall           // assistant 的工具调用
    Images       []string             // 当前用户消息的图片 URL
}
```

### 实现层次

```
Chat 接口
  ├── OllamaChat      → 本地 Ollama 部署（/api/chat）
  └── RemoteAPIChat   → OpenAI 兼容 API
        │
        └── ProviderSpec 注册表（chat_provider_spec.go）
              ├── 请求定制：注入 thinking 参数、改 max_tokens 字段名
              ├── 端点定制：/v1/chat/completions → 厂商特定 URL
              └── 响应定制：处理非标准 SSE 格式
```

### 工厂函数

```go
// NewChat 根据 Source 字段自动选择 Ollama 还是 Remote
func NewChat(config *ChatConfig, ollamaService *ollama.OllamaService) (Chat, error)

// ConfigFromModel 从 types.Model 构造 ChatConfig（生产/测试共用）
func ConfigFromModel(m *types.Model, appID, appSecret string) *ChatConfig
```

### 装饰器链

```
NewChat → wrapChatDebug → wrapChatLangfuse
              │                │
         日志调试输出      Langfuse 追踪
```

## 二、Embedding 接口（embedding/embedder.go）

### 接口定义

```go
type Embedder interface {
    Embed(ctx context.Context, text string) ([]float32, error)
    BatchEmbed(ctx context.Context, texts []string) ([][]float32, error)
    GetModelName() string
    GetDimensions() int
    GetModelID() string
}
```

### 实现清单

```
Embedder 接口
  ├── OllamaEmbedder        → 本地 Ollama
  ├── OpenAIEmbedder        → OpenAI 兼容（默认兜底）
  ├── AliyunEmbedder        → 阿里云 DashScope（多模态专用）
  ├── JinaEmbedder          → Jina AI
  ├── VolcengineEmbedder    → 火山引擎 Ark
  ├── AzureOpenAIEmbedder   → Azure OpenAI
  ├── NvidiaEmbedder        → NVIDIA
  └── WeKnoraCloudEmbedder  → WeKnora 云端
```

### 工厂路由逻辑（NewEmbedder）

```
Source=Local → OllamaEmbedder
Source=Remote → 识别 Provider：
  aliyun    → 多模态模型走 AliyunEmbedder，纯文本走 OpenAIEmbedder
  volcengine → VolcengineEmbedder
  jina      → JinaEmbedder
  azure     → AzureOpenAIEmbedder
  nvidia    → NvidiaEmbedder
  weknoracloud → WeKnoraCloudEmbedder
  其他       → OpenAIEmbedder（兼容）
```

## 五、ASR 接口（asr/asr.go）

语音转文字，用于语音输入提问。

### 接口定义

```go
type ASR interface {
    Transcribe(ctx context.Context, audioBytes []byte, fileName string) (*TranscriptionResult, error)
    GetModelName() string
    GetModelID() string
}

type TranscriptionResult struct {
    Text     string    `json:"text"`     // 完整文本
    Segments []Segment `json:"segments"` // 带时间戳的分段
}
```

### 实现

```
ASR 接口
  └── OpenAIASR → 调用 /v1/audio/transcriptions（OpenAI 兼容）
```

目前只有一个 OpenAI 兼容实现，因为所有主流厂商的 ASR 都跟 OpenAI 的 `/v1/audio/transcriptions` API 格式一致。

## 六、Provider 注册表（provider/provider.go）

**支持 22 个厂商**，统一管理每个厂商的元数据 + 自动检测。

### 核心机制

```go
type Provider interface {
    Info() ProviderInfo
    ValidateConfig(config *Config) error
}

type ProviderInfo struct {
    Name         ProviderName               // 标识
    DisplayName  string                     // UI 展示名
    DefaultURLs  map[types.ModelType]string // 每种模型类型的默认 API 地址
    ModelTypes   []types.ModelType          // 支持的模型类型
    RequiresAuth bool
    ExtraFields  []ExtraFieldConfig         // 额外配置字段
}
```

### 三步路由流程

```
1. 用户选择 Provider（如 "aliyun"）
      ↓ (如果为空)
2. DetectProvider(BaseURL) 自动检测
   根据域名匹配 → zhipu / deepseek / siliconflow / ...
      ↓
3. 各能力线的工厂函数根据 Provider 路由到具体实现
```

## 七、装饰器体系

每个能力线都有相同的装饰器链：

```
原始实现 → LLMDebug 装饰器 → Langfuse 装饰器 → 返回给上层
```

| 装饰器 | 条件 | 作用 |
|---|---|---|
| `wrapChatDebug` / `debugEmbedder` 等 | `LLM_DEBUG=true` 环境变量 | 控制台打印完整请求/响应 |
| `wrapChatLangfuse` / `langfuseEmbedder` 等 | Langfuse 已启用 | 上报 Token 消耗、延迟、错误到 Langfuse |

### 启用方式

```bash
# 开启 LLM 调试日志（打印每次 API 调用的请求体和响应体）
export LLM_DEBUG=true

# Langfuse 通过配置启用（见 config/config.yaml）
```

## 八、工厂模式总结

所有能力线遵循完全一致的创建流程：

```
types.Model（DB 持久化）
    │
    ▼
ConfigFromModel(m, appID, appSecret)  →  能力线专属 Config
    │
    ▼
NewXxx(config, ...)                   →  工厂函数
    │  1. Source=Local  → Ollama 实现
    │  2. Source=Remote → 识别 Provider → 路由到具体实现
    │  3. 包装 LLMDebug 装饰器
    │  4. 包装 Langfuse 装饰器
    ▼
返回统一接口
```

### 模型类型 → 能力线映射

| types.ModelType | 使用的接口 | 工厂函数 |
|---|---|---|
| `KnowledgeQA` | `Chat` | `chat.NewChat()` |
| `Embedding` | `Embedder` | `embedding.NewEmbedder()` |
| `Rerank` | `Reranker` | `rerank.NewReranker()` |
| `VLM` | `VLM` | `vlm.NewVLM()` |
| `ASR` | `ASR` | `asr.NewASR()` |
