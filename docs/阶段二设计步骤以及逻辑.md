## 三、模块5：Agent 引擎 + Skills（Week 1-2，★ 核心）

### 3.1 目标与交付标准

**目标**：实现 ReAct 推理循环，让 Agent 自主决定"是否检索、调什么工具、何时给出最终答案"。

**交付标准**：创建 Agent → 配置工具和技能 → 提问 → ReAct 多步推理 → 答案；100 轮对话后仍不丢上下文（与甲的短期记忆联调后验证）。

### 3.2 设计要点

#### 3.2.1 ReAct 循环实现方案 ✅ 已决策：ADK ChatModelAgent（2026-08-05 调研定稿）

**调研结论**：eino v0.9.13 已内置两代 Agent 框架，最终选择新一代 **ADK（Agent Development Kit）** 的 `ChatModelAgent`：

| 方案 | 结论 |
|---|---|
| 老 `flow/agent/react` | ❌ 弃用：无事件流、无官方 skill/summarization 中间件，官方主推 ADK |
| 手写 `compose.Graph` 循环 | ❌ 弃用：循环逻辑（终止条件、工具结果回填）要自己实现，收益低 |
| **ADK `ChatModelAgent`**（`adk.NewChatModelAgent`） | ✅ **采用**：官方新一代 ReAct，事件驱动（`AsyncIterator[*AgentEvent]`）天然适合 SSE 推送推理过程；`MaxIterations` 控制最大步数；内置中断/恢复（Runner + CheckPointStore，IM 长任务可用）；`Model` 直接喂 `ChatModelFactory` 的 `ToolCallingChatModel` |
| ADK `prebuilt/deep`（DeepAgent） | ❌ 暂不用：它是**多 Agent 编排模式**（Main Agent + WriteTodos 任务分解 + TaskTool 委派 SubAgents），适用于多角色协作；本模块是单 Agent + 工具集场景，使用会造成过度分解、增加 LLM 调用成本。**留作 v2 扩展点**（复杂任务自动分解） |

**ADK 红利（与思维导图设计精准对应）**：
- `adk/middlewares/skill` — 官方 Skills 系统（SKILL.md front matter + 渐进式披露），覆盖思维导图 read_skill 三级设计，**不自研解析器**
- `adk/middlewares/summarization` — 对话摘要压缩，**甲模块1（短期记忆）可直接采用**，需与甲对齐（见 3.4）
- `adk/middlewares/reduction` — 上下文缩减（大工具结果截断），对应思维导图 Token 管理
- 工具接口为 `tool.BaseTool`：用 `utils.InferTool` 可从普通 Go 函数生成；甲的老 `Tool` 接口通过薄适配层接入

> 引擎统一基于 ADK 封装：从 `entity.AgentConfig` 动态构造 `adk.ChatModelAgentConfig`（Model / Instruction / ToolsConfig / MaxIterations / Middlewares）。
>

#### 3.2.6 交互与可控性设计（企业级，参考 `agent编排注意事项.md`）

> 原则：RAG 只占 Agent 系统的 20%，其余是用户体验、可靠性、可控性。以下能力**随 Agent 引擎一起交付**，不做成 Demo 玩具。

**① Agent 状态机（前端 UI 刷新依据）**

```
INIT → Thinking（LLM 推理中）→ Searching（检索/工具执行中）→ Generating（生成中）
     → Completed / Cancelled / Failed
```

- 状态随 SSE 事件推送（`response_type: state`），前端按状态渲染"🤔 正在思考 / 📚 正在查询知识库 / ✍️ 正在组织答案"
- 实现：ADK `AgentEvent` 事件流天然携带节点输出，runner.go 中映射为状态事件

**② 中断回答（Abort）⭐ 企业必备**

- 阶段一 `StopChat` 是空实现，阶段二必须真正实现：`POST /sessions/:id/stop` → `context.Cancel()` → 取消 LLM / 检索 / 工具执行 / Workflow
- 所有节点（工具、检索、LLM）必须监听 context；ADK Runner 对 ctx 取消的原生支持需在 Day 10 验证
- 中断后状态置 `Cancelled`，前端立即停止渲染

**③ 重新生成（Retry）与继续回答（Continue）**

- Retry：**不重新检索**，沿用已有检索结果 + 重新拼 Prompt → 重新生成（速度快、省成本）
- Continue：模型输出被截断时，携带剩余上下文继续生成
- 均复用当前 Session 已保存的搜索结果，不重复走 RAG

**④ 敏感词过滤**

- 输出层过滤：命中敏感词（薪资/裁员等，可配置）→ 拒绝回答或模糊化
- 词表放 `configs/sensitive_words.yaml`（可配置）；**注意：流式已推送内容无法撤回**，命中后只能停止生成 + 发修正/error 事件；工具输出层可先整体校验再透传

**⑤ 幻觉控制与检索无结果降级**

- kb_search 无结果 / 分数低于阈值时：**明确告知"未找到相关资料，以下内容仅供参考"**，禁止 LLM 编造
- 由 `FallbackStrategy`（默认 llm_only / fixed_response）驱动，`FallbackResponse` 作为固定兜底文案
- 工具执行失败（LLM 超时 / 检索异常）→ 降级提示"服务暂时不可用，请稍后重试"，不返回 500

**⑥ 引用溯源与置信度**

- Agent 最终回答的 SSE 事件必须携带 `references`（来源文档 + 分数），与阶段一 `KnowledgeReferences` 格式一致
- 引用数、Top-K 分数随 `agent_steps` 记录，前端可展示"引用文档数量：3"

**⑦ Token 与耗时统计**

- `agent_steps` 每条记录：工具耗时、token 消耗（LLM 响应中提取）、步骤耗时
- 汇总到 Session 级统计（可选展示），Langfuse 全链路追踪由甲负责（模块9 可观测性）

#### 3.2.7 AgentEvent → SSE 事件映射（runner 层封装要点，2026-08-06 源码调研）

> 数据来源：eino v0.9.13 `adk/interface.go`、`adk/utils.go`；SSE 协议见 `internal/api/v1/chat/controller.go`。

**① 消费 API 不同，controller 消费循环必须重写**

| | 阶段一 pipeline | ADK Agent |
|---|---|---|
| 类型 | `*schema.StreamReader[*schema.Message]` | `*adk.AsyncIterator[*adk.AgentEvent]` |
| 消费 | `Recv() (msg, err)`，`io.EOF` 结束 | `Next() (event, bool)`，bool=false 结束 |
| 错误 | Recv 返回 error | 错误在 `event.Err` 字段，Next 不返回 error |

**② 一个 AgentEvent ≠ 一条 SSE（粒度不对等）**

- `event.Output.MessageOutput`：`IsStreaming=false` → 完整消息（content + 多个 tool_calls）；`IsStreaming=true` → `MessageStream` 需再逐 chunk 消费
- 展开规则：`Role==schema.Assistant` → answer 增量 / thinking；`Role==schema.Tool` → agent_step 事件（流式模式下消息未物化，`ToolName` 是唯一标识工具的方式）

**③ MessageStream 独占消费，且必须消费完**

- 一个事件只能一个消费者（官方注释 MUST be exclusive）；不消费会阻塞 Agent 后续步骤（背压）
- 官方建议 `SetAutomaticClose()`（事件未处理时流自动关闭，防泄漏）
- **tool_call 是流式增量到达**：多 chunk 需合并（`schema.ConcatMessages` / `GetMessage()`）才是完整参数，否则 agent_steps 工具参数残缺；拼接后不可再消费

**④ EnableStreaming 必须显式开启**：`AgentInput.EnableStreaming` 与 `RunnerConfig.EnableStreaming` 均需为 true；IM 场景（飞书）可直接非流式，省展开开销

**⑤ 终止 / 错误 / 中断语义**

- `Next()` bool=false → 正常结束 → SSE `complete`
- `event.Err != nil` → SSE `error`
- `event.Action`：`Exit` / `Interrupted` / `BreakLoop`；`Interrupted` → 状态机 `Cancelled`
- 用户点停止：`ctx.Cancel()` → 事件流结束（可能带 `context.Canceled`），与 3.2.6 ② Abort 呼应

**⑥ references 时序变化（前端适配）**：阶段一是"同步检索完 → 先发 references → 再流式答案"；Agent 模式检索是循环中的工具调用 → references **迟到且可能多次**，SSE 协议改为"每轮工具结果即发"

**⑦ HTTP 侧**：长思考需 SSE 心跳（`: ping` 注释行，nginx proxy_read_timeout 默认 60s）；`c.Request.Context().Done()` 需显式 cancel Agent Run；敏感词流式校验无法撤回已推送内容（见 3.2.6 ④）

**⑧ 接口签名扩展**：`KnowledgeChat` 现返回 `(*schema.StreamReader[*schema.Message], []VectorSearchResult, error)`，smart-reasoning 分支需新增返回 `AsyncIterator` 的接口（chat_service_interface.go）

## 四、模块6：MCP 服务（Week 2-3）

### 4.1 目标与交付标准

**目标**：将知识库检索能力暴露为 MCP Server，让外部客户端（Claude Desktop 等）能调用 DocMind；同时管理外部 MCP Client 的注册与启停。

**交付标准**：Claude Desktop 通过 MCP 连接 DocMind，搜索知识库并返回结果。

### 4.2 设计要点

**Server 侧（对外暴露）：**
- 协议：SSE 传输（HTTP 长连接）；Go 实现优先调研 `mark3labs/mcp-go` 库，避免手写协议细节
- 工具暴露：`kb_search`（知识库检索，参数：query / knowledge_base_id / top_k）→ 复用阶段一检索能力
- 资源暴露：知识库列表、chunk 内容作为 Resource（`docmind://kb/{id}`）
- 认证：与系统 JWT 对齐（API Key 或 Bearer Token）
- **权限隔离**：kb_search 必须携带用户上下文，检索时按 UserID 过滤知识库（复用 `PipelineVectorSearchParams.UserID`），防止越权访问
- 入口：独立端口或同端口 `/mcp` 路由，注册进 `internal/api/router.go`

**Client 侧（调用外部）：**
- 管理外部 MCP Server 连接（stdio / SSE）的注册、启停、健康检查
- 与甲模块3"MCP 工具加载"的分工：**甲负责把外部 MCP 工具适配进 Agent 工具注册表，乙负责连接生命周期管理** —— 通过甲的工具注册表接口协作
- 新增表 `mcp_services`：`name`、`transport`(stdio/sse)、`command`/`url`、`enabled`、`tools`(json 缓存)
- `entity.AgentConfig` 已有 `MCPServices` / `MCPSelectionMode` / `MCPAuthWaitTimeout` 字段，直接映射

### 4.3 实施步骤

1. 调研并引入 mcp-go（或同类库），确认 SSE Server 支持度
2. MCP Server：注册 `kb_search` 工具 + 知识库资源，本地自测（mcp 客户端连上 → 调工具 → 返回 chunk）
3. `mcp_services` 表 + Repository + CRUD API
4. MCP Client 管理：连接池、启停、工具列表同步
5. 与 Agent 引擎打通：Agent 的 `MCPServices` 配置 → 动态注册外部工具
6. 文档：外部客户端接入说明（Claude Desktop 配置示例）

## 五、模块8：IM 集成层（Week 3-4）

### 5.1 目标与交付标准

**目标**：通过飞书、企微等 IM 工具与知识库对话。

**交付标准**：飞书群 @机器人提问 → 检索知识库 → 返回答案到群。

### 5.2 设计要点

- **IMAdapter 接口**（`internal/im/` 新包）：

```go
type IMAdapter interface {
    SendMessage(ctx context.Context, target, content string) error
    ReceiveMessage(ctx context.Context) (<-chan *IMMessage, error)  // webhook 入口
    FormatConvert(raw *IMMessage) (*service.KnowledgeChatRequest, error)
}
```

- **飞书适配器**：事件订阅 Webhook（接收 @机器人消息）→ 回调地址 `/im/feishu/callback`；发送走机器人 API（tenant_access_token + message API；注：`tenant_access_token` 为飞书平台应用凭证名，与系统租户无关 —— 本项目为**单租户架构**）
- **企微适配器**：接收回调 + 回复；支持引用回复（`msgtype: text` + 引用消息 ID）
- **会话绑定**：新增表 `im_bindings`：`platform`、`platform_user_id`、`user_id`、`session_id`、`kb_ids`(json)；IM 用户首次提问自动建会话（复用 `CreateSession`）
- **消息队列**：Webhook 收到消息 → 入队 → 异步处理 → 回复。阶段二先用**内存队列**（buffered channel + worker pool）实现削峰，预留 Redis 队列切换点（接口 `MessageQueue`）
- 无真实凭据时提供 **Mock 适配器**：HTTP 模拟入口，便于联调

### 5.3 实施步骤

1. `internal/im/` 包：IMAdapter 接口 + 消息模型 + MessageQueue 接口（内存实现）
2. 会话绑定表 + 映射逻辑
3. 飞书适配器（webhook 接收 + 发送），本地 Mock 验证
4. 企微适配器（接收 + 引用回复）
5. 统一入口 `POST /im/callback`（按 platform 分发）→ 入队 → 调 `KnowledgeChat` → 回复
6. 文档：飞书/企微后台配置步骤

## 六、联调与端到端验收（Week 5-8）

### 6.1 Agent 全流程联调清单（Week 5-6）

- [ ] Agent 提问 → ReAct 循环 → 检索工具 → 多步推理 → 最终答案（SSE 流式）
- [ ] 甲的工具集（≥4 工具）注册进引擎，`AllowedTools` 白名单生效
- [ ] 短期记忆：长对话自动摘要压缩，Token 不超限（甲的 Consolidator）
- [ ] 长期记忆：跨会话"上次讨论的 X"（甲的 MemoryService）
- [ ] Skills 注入：选中技能后行为变化可见
- [ ] MCP 工具：外部 MCP Server 连接 + 工具可调
- [ ] 兜底：LLM 调用失败 → FallbackResponse 生效
- [ ] Abort：生成中停止 → LLM/检索/工具全部取消，状态置 Cancelled
- [ ] Retry：停止后重新生成，不重复检索
- [ ] 状态机：SSE 依次推送 Thinking → Searching → Generating → Completed
- [ ] 敏感词：命中词表 → 拒绝/模糊化
- [ ] 无结果降级：kb_search 无结果 → 明确告知，不编造
- [ ] 引用溯源：Agent 回答带 references（来源 + 分数）；检索在循环中 → references 迟到/多次，前端适配

### 6.2 端到端测试（Week 6-8）

- 创建自定义 Agent → 配置模型/工具/技能 → 提问 → 多步推理 → 答案 + 步骤回放
- MCP：Claude Desktop（或 mcp 客户端）连接 → kb_search
- IM：飞书/企微（或 Mock 适配器）@机器人 → 问答返回
- 性能：长会话 Token 不超限、检索延迟、并发提问稳定性

## 七、风险与协作边界

| 风险/依赖 | 说明 | 应对 |
|---|---|---|
| ADK 版本稳定性 | ADK 为较新框架，API 可能随 eino 升级变动 | 锁定 eino v0.9.13（go.mod 已固定）；封装层隔离，升级时只改 engine.go 适配 |
| 甲的接口交付延迟 | Tool / Consolidator / MemoryService 未按期 | 乙 Week 1-2 全程用 mock 工具开发，接口先行约定 |
